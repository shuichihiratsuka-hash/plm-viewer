# plm-viewer

`plm-gas`（社内の PLM）から開く **3D / 図面のビューア**。GitHub Pages で配信します。

**→ https://shuichihiratsuka-hash.github.io/plm-viewer/**

## なぜ plm-gas の外に置くのか

`plm-gas` は Apps Script のウェブアプリで、画面が `googleusercontent.com` の
iframe の中で動きます。そのため：

- `drive.google.com` への `<img>` / `fetch` は**別サイトへの要求**になり、
  ブラウザが Drive の Cookie を送らないので**非公開ファイルは 403** になる
  （2026-08-22 に iOS Safari で実測）
- 回避のためサーバ（GAS）で中継すると、`google.script.run` の
  **ペイロード上限**に当たる。⚠️ 実データは**治具1点で 10.5MB**、組立はさらに大きい

**Drive API は CORS に対応している**ので、ページから直接 `files.get?alt=media` を
叩ければ中継が要らず、上限も消えます。それには plm-gas とは別の
**普通のオリジン**が必要で、その置き場がここです。

## できること（★2026-08-23 に両方とも実測できた）

| 入口 | どう使うか | 実測（iPhone・`めっき治具_L0.stp` **10.5MB**）|
|---|---|---|
| **ファイルを選ぶ** | 端末のファイルを選んで描く | WASM 0.3秒 ＋ 変換 5.4秒 ＝ **5.7秒**（三角形 140,046 / 頂点 113,558）|
| **`#id=<DriveのファイルID>`** | Drive から**直接読んで**描く | ダウンロード 1.4秒 ＋ 変換 5.6秒 ＝ **7.1秒** |

`plm-gas` からは後者で開きます（`coreOpen3d` が `#id=` を付けた URL を別窓で開く）。
初回だけ Google の許可を1回聞かれます（`drive.readonly`）。

⚠️ **組立はまだ測っていません。** 上は治具1点の数字で、大きさが1桁違うと
別の壁に当たり得ます（測ったらここに追記してください）。

読めるのは **STEP / IGES / GLB / glTF** です
（`.stp` `.step` `.igs` `.iges` `.glb` `.gltf`）。

| 形 | 読み方 | 向くもの |
|---|---|---|
| `.stp` `.step` `.igs` `.iges` | occt（WASM）で**毎回変換**して読む | 単品〜中くらいの組立 |
| `.glb` `.gltf` | `GLTFLoader` で**そのまま**読む（変換なし＝速い）| **大きい組立**・Draco 圧縮 |

⚠️ GLB は**変換済みの写し**です。**版（Rev）が入りません。**
   誰がいつ何の版から作ったかは **PLM 側で記録する**必要があります
   （ビューアは知りようがない）。

## E-BOM 突き合わせ（2026-08-24）

**貼り付けて比べるだけ。何も保存しません。**
本人の指示：「同じ名前でありなし、クリアの表示はするか
（その時だけで、フラグとしては持たない）」

| できること | 中身 |
|---|---|
| ○ 両方にある | 名前が一致した品目。**数量も照合**（BOM の数量 vs モデルの節点の数）|
| ▲ モデルだけにある | **E-BOM 漏れの候補** |
| ▼ E-BOM だけにある | モデル未反映、または形の無い品目（O リング等）|
| 行を押す | その部品をツリーの☑にする →「選択以外を透過」で 3D で追える |
| 「モデルだけを☑」 | 漏れ候補を一括で選ぶ |

**名前を揃える規則**（ここが精度をほぼ決める）
NFKC で全角→半角・小文字化 → CAD の拡張子（`.SLDPRT` 等）を落とす →
記号・空白・括弧を落とす。実体の連番（`_1`）は**落とした鍵も併記**して引く
（落とすのを主にすると `治具_12` のような正しい名前を壊す）。

⚠️ **やらないこと（同じ強さで残す）**

| やらない | なぜ |
|---|---|
| **階層（親子）の照合** | CAD の組立の括り方と E-BOM の括り方は一致しない。照合すると**正しいのに不一致**が大量に出て使えなくなる |
| **図番を主にした照合** | 実物の節点名は CAD のファイル名（`めっき治具_トップフランジ` / `（ミスミ）PTFH6-20_六角樹脂ボルト`）で**図番が入っていない**。図番は名前で当たらなかったときの副の手掛かり |
| **版（Rev）の照合** | STEP / GLB に版が入っていない |
| **結果を残す** | 🔴 本人の指示。`localStorage` にも書かない。モデルを読み直すと消える |

⚠️ モデル側の個数は**節点の数**です。CAD が並び（パターン）を1節点にまとめて
   いると実数と合いません。画面にもそう出しています。

### 🔴 GLB を通ると部品名が**削られる**（three.js の仕様）

`GLTFLoader` は節点名を `THREE.PropertyBinding.sanitizeNodeName` に通します。
実測（three 0.185.1・その場で関数を呼んで確認）：**`. [ ] : /` を消し、空白を `_` に**。

| CAD のファイル名 | GLB を読んだ後の節点名 |
|---|---|
| `めっき治具_トップフランジ.SLDPRT` | `めっき治具_トップフランジSLDPRT` |
| `めっき治具 底板` | `めっき治具_底板` |
| `A[1].B` | `A1B` |
| `治具/工程図` | `治具工程図` |

⚠️ **これは直せません**（three.js がアニメーションの経路名に使うため）。
⇒ `bomKey` は**記号を全部落としてから拡張子の綴りを落とす**順にしてあります。
   逆順だと `\.sldprt$` に当たらず、**同じ部品が「モデルだけ」と
   「E-BOM だけ」の両方に出ます**（最悪の出方。在るのに漏れと欠品の両方に見える）。
   2026-08-24、**本番サイトに実物の GLB を読ませて**捕まえました。

★E-BOM は**貼り付け**で渡します（このページは GAS を呼びません。
  サーバに何も送らない性質を崩さないため）。将来 `plm-gas` から
  `postMessage` で渡すなら、受け口は `bomParse()` の1本で足ります。

## 見る道具（2026-08-24 に追加）

| | 中身 |
|---|---|

### 操作の置き方（AutoDesk に寄せた）

**下に絵＋文字のバー**：ホーム / フィット / 画面移動 / ズーム / オービット /
向き / 断面 / 計測 / 分解 / モデル。**選んだ道具の設定だけが1段上**に出る。
上のバーは**入口**（STEP を選ぶ / Drive から）と**白背景**と**スクリーンショット**だけ。

- 画面移動・ズーム・オービットは **`OrbitControls` の左ドラッグの割当を差し替える**
  （モードを選ぶ操作感）。カーソルも変える。⚠️ スマホの1本指も合わせる
- ⚠️ 640px 以下は文字を落として絵だけにする（横に入らない）
- 🔴 **慣性（`enableDamping`）は切る。** 「ふわふわする」と言われた原因。
  離しても動き続けるので狙った所で止まらない。**処理のラグではない**
- 🔴 **設定の段は作り直すので、結線は `#opt` への委譲でまとめる。**
  都度 `addEventListener` すると**二重に効く**（押すと2回動く）

### ViewCube（右上の向きの箱）

いまどこから見ているかが**常に分かる**。面を押すとその向きから見る。

- ⚠️ **`renderer` は増やさない**（WebGL の文脈が増える）。同じ renderer の
  右上の一角に `setViewport` / `setScissor` で描く
- 🔴 **投影の枠は箱にぴったり合わせる。** 枠が箱より大きいと
  **一角の外周に箱の無い帯**ができて、そこを押しても当たらない
  （実際に踏んだ。原因は当たり判定ではなく**枠**）。
  斜めから見た半対角は `size × √3/2` なので、枠 ±1.0 に対して `size = 1.15`
- 🔴 **当たり判定の前に行列を自分で最新にする。**
  向きは描画ループが更新しているが、**タブが裏に回ると `requestAnimationFrame`
  が止まる**ので、フレームが1つも走っていない状態で押されることがある。
  行列が古いと**静かに外れる**（押しても何も起きない）
- ⚠️ 軸の呼び方はモデル依存。three.js の既定（**Y が上**）で
  上＝+Y / 前＝+Z / 右＝+X とし、画面にもそう出す

### 計測（距離・角度・座標）

🔴 **値は必ず `~` を付ける。** AutoDesk Viewer も `~ 21.0 mm` と出している。
理由は同じで**三角形に割った形の上で測っている**から。
⚠️ 厳密に見せると、拾った点が稜線から少し外れているだけで数字が独り歩きする。
★設定の段に「**およその値です**」と常に出してある。

- 点は**三角形の頂点にスナップ**（12px 以内）。平面の角や穴の縁は
  **元の位置がそのまま残っている**ので、拾えれば精度が出る
- ⚠️ 円筒の面の途中を拾うと**弦**を測る（避けようがない）
- ⚠️ **回した（4px 超動かした）ときは拾わない**（OrbitControls と取り合いになる）
- ⚠️ **見えていないものは拾わない**（ツリーで消した部品を測らせない）
- ⚠️ 単位は occt が返した長さの単位（既定はミリ）。**STEP の単位を読み替えていない**

### 分解

中心から各部品の中心へ向かう方向に、割合で離す。
⚠️ **離す単位は「葉の部品」**（メッシュ単位で離すと1つの部品がばらける）。
⚠️ **断面のステンシルは作った時の行列を覚えている**ので、離したら更新する
（`secSyncMatrices`。しないと蓋が元の場所に残る）。

### 表示の細かい設定（既定は素のまま）

**ワイヤー** / **エッジ強調** / **選択以外を透過** / **選んだ部品を隠す・だけ表示・全部表示**。
★**既定は今のまま。** 細かく見たい人のために「表示」の段に隠してある。

- ⚠️ **エッジ強調は重い**（`EdgesGeometry` を全メッシュ分作る）。
  **60万三角形を超えたらやらずに断る**（黙って固めない）。折れ角 20度以上の稜線だけ描く
- ⚠️ **見えていない部品にはエッジを付けない**（隠した部品の線が浮く）
- ⚠️ 断面を切っているときは**線も切る**（線だけ残ると読めない）
- ⚠️ 透過は `depthWrite = false` にする（しないと後ろが消える）
- ★複数選択は**ツリーの ☑**。その節点の**下も一緒に**選ぶ（サブ組立をまとめて選べる）。
  ⚠️ 名前を押す操作（isolate）は**変えていない**（覚え直させない）

### GLB で書き出す（`GLTFExporter`）

★**このビューアでできる。** 読み込んだあと「表示 → GLB で書き出す」。

- ⚠️ 出るのは**三角形**（occt が返すのがそれ。**B-rep は入らない**）
- ⚠️ **断面・エッジ・計測は入らない**（`model` だけ渡している）
- ⚠️ **分解した状態で書き出すと離れたまま**保存される（そう出す）
- 🔴 **これは 2.29GB の STEP を救わない。** 読めないものは書き出せない
  （ブラウザがバイト列を持てないので、そもそも開けない）。
  ⇒ **開けるものを次から速く開くため**の機能。大物は CAD 側（CAD Assistant /
  FreeCAD headless）で変換する
- ⚠️ **GLB は写し。** STEP を改訂したら作り直さないと**古い形を見せる**。
  `PART_DOC` に登録するなら「**どの版の STEP から作ったか**」を残すこと

### 背景（暗い／白）

用途が「**手順書に貼る**」なので、薄いグレーではなく**純白**。既定は暗い色。覚える。
⚠️ 白にすると**破線の枠**（水色）が消えるので**色も一緒に切り替える**。
⚠️ 白地は陰影が弱いと立体に見えないので、環境光を落として平行光を上げる。
⚠️ スクリーンショットは canvas をそのまま取るので、**この色がそのまま入る**。

### 大きさの関門（`sizeGate`）

🔴 **落としてから失敗するのをやめる。** 2.29GB の STEP が `Failed to fetch` になった。
限界が3つ重なっている：

1. `arrayBuffer()` は**1本の連続した領域**。ブラウザの上限は概ね **2GB（2³¹−1）**
2. 通っても occt（WASM）へ**丸ごとコピー**する ＝ 約2倍。**WASM32 は 4GB が上限**
3. 通っても三角形が出る。治具 10.5MB で 140,046 なので 2.29GB は**3千万三角形**規模

⇒ **800MB 超で止め**、理由と代わりの手（サブ組立に分ける／glTF・GLB で書き出す／
専用のビューアを使う）を出す。**150MB 超は警告して通す**
（どこで壊れるかは実測していないので勝手に諦めない）。

⚠️ **ダウンロードはブラウザに残らない。** Drive API の応答は認証付きで `private` 相当だし、
そもそも**メモリに読んでいる**（ディスクに置いていない）。**押し直すと丸ごと落ち直す。**

### 下のログ欄

既定は**3行ぶん**。境界を掴んで上下に動かせる（畳める・覚える）。
ログは**500行で古いものから捨てる**。
🔴 **ライセンスの表示は畳む対象の外**（LGPL-2.1 / MIT の表示は義務）。

### ★カメラを動かす。モデルは回さない
断面の面はワールドに固定したいので、モデルを回すと
**「部品に対してどこを切ったか」が分からなくなる。**
⚠️ 真上・真下から見るときは `up` を変える（`up` と視線が平行だと絵が消える）。
軸回転では `up` も一緒に回す（回すたびに絵が起き上がらないように）。

### 🔴 断面の蓋（ステンシル）

`clippingPlanes` で切るだけでは**中が透けて中空の殻に見える**。断面図として
読めないので、three.js の定石で切り口を塗る（裏面 +1 / 表面 −1 で中身を数える）。

🔴 **`WebGLRenderer` に `stencil: true` を明示すること。**
three.js は **r163 から既定が `false`** になった。バッファが無いと
ステンシルテストが**常に通る**ので、**蓋が画面全体を覆う**（実際に踏んだ）。

🔴 **部品ごとにグループと蓋を作り、蓋を描いたあとで `clearStencil()` する。**
1組にまとめると**部品をまたいで数が混ざり**、視線方向に重なった部品
（穴に入ったボルトなど）で**中身なのに 0 になって蓋が抜ける**。

- 蓋の色は**その部品の色から作る**（橙へ 35% 寄せる）。部品の色そのままだと
  「切った所」だと分からず、橙一色だと部品を見分けられない
- ⚠️ **モデル本体は全部の蓋より後に描く**（先に描くと蓋に隠れる）
- ⚠️ 部品ごとに裏・表・蓋で**描画が3倍**になるので、**60個を超えたら1色にまとめる**。
  まとめると上記のとおり切り口が抜けることがあるので**画面に出す**
- ⚠️ **隠した部品の蓋も消す。** 蓋はモデルの外に置いているので、
  ツリーで消しても**蓋だけ残って切り口が浮く**（先祖まで辿って見えているかを見る）

### 🔴 組立の階層（ASSY）は捨てない

`occt-import-js` は **`result.root` に `{name, meshes:[番号], children:[...]}`** の
木を返す。⚠️ 以前は `result.meshes` を平らに回していたので、
**どの部品がどのサブ組立に属するか**が分からなくなっていた。

- ⚠️ **頂点はすでにワールド座標**なので `Group` に変換を載せない（二重に動く）。
  木は「まとめ方・名前・表示の入り切り」に使う
- ⚠️ **`root` を返さない版でも動くように**、平らな読み方も残す（その旨を出す）
- ★**葉はまとめる。** occt は「部品」も `Group` で返し、その下に名前のない `Mesh` が
  1つ入るので、両方を行にすると**部品ごとに2行**出て読めない
- ⚠️ **STEP の名前は人が付けている。** HTML に出す前にエスケープする

### 🔴 寸法測定の精度について（未実装だが先に押さえておく）

**STEP は厳密な形状（B-rep：平面・円筒・NURBS の式と座標）を持っている。**
落ちるのは変換の段：`occt-import-js` は OCCT の `BRepMesh_IncrementalMesh` で
**三角形に割った結果しか返さない**（`attributes` / `index` / `brep_faces`。
**厳密な稜線や頂点は入っていない**）。

⇒ **三角形の点を2つ拾って測ると、円筒では弦を測ることになり真の直径より小さく出る。**
誤差は `linearDeflection` 次第。

★**`brep_faces`（B-rep の面ごとの三角形の範囲）があるのが効く。**
点を拾うのではなく**面に当てはめて測れば**精度が戻る：

| 測るもの | 方法 | 精度 |
|---|---|---|
| 平面どうしの距離 | 面の三角形に**平面を当てはめる** | ほぼ厳密（平面の頂点は元の位置）|
| 穴・軸の直径 | 円筒面の三角形に**円を当てはめる** | ほぼ厳密（点を2つ拾うより桁違いに良い）|
| 自由曲面 | 近似のまま | 近似 |

⚠️ **「参考値」として出すか「検査に使える値」として出すかを先に決めること。**
参考値のものを検査に使われると事故になる。画面の文言まで含めて決める。

## 🔴 2GB 級の STEP をどうやって見るか（`めっき治具` の実物で 2,291.1MB）

**ブラウザでは読めません。** `sizeGate` が 800MB で止めますが、外しても
`arrayBuffer()` の 2GB 制限と WASM32 の 4GB 制限に当たります（下の「大きさの関門」）。
⇒ **GLB にしてから持ってくる**のが唯一の道です。ビューアは GLB を読めます。

### 🔴 まず測った数字（推測ではない・2026-08-24 実測）

| 何 | 実測 | 意味 |
|---|---|---|
| **1本の `ArrayBuffer` の上限** | **2046MB**（2³¹−1 のすぐ下）| **2291MB は JS のメモリに載せる段階で失敗する** |
| WASM メモリの伸び | 4096MB まで伸びた | occt の空間。ただし上の壁が先に来る |
| `memory64` | 使える | ⚠️ `occt-import-js` は **32bit ビルド**なので関係ない |

🔴 **これは occt に渡す「前」の壁。** だから**ビューアに何を実装しても越えられない。**
「変換をビューアでやれば？」の答えは「**変換はもう入っているが、
2GB 級はその手前で読めない**」です。

### ★変換はビューアの中でできる（外のサイトは要らない）

「**ファイルを選ぶ**」で STEP を読む（occt がその場で変換）
→ 表示 →「**GLB で書き出す**」→ その GLB を「ファイルを選ぶ」で開く。
**ファイルは端末から出ません**（このページはサーバに何も送らない）。

さらに「**選んだ部品だけ GLB**」で、ツリーで☑した部品だけを書き出せます。
⇒ 読める大きさの組立なら、**ビューアの中でサブ組立に割れます**。
⚠️ 元のモデルは触りません（`clone()` で写すので位置関係もそのまま）。

### 手順（上から順に試す。上のほうが速くて質がよい）

**① 元の CAD から直接 glTF / GLB で書き出す（★最善）**
SolidWorks 2019 以降・Inventor・Creo・NX は glTF / GLB を直接書き出せます。
STEP を経由しないので**部品名と階層がきれいに残り**、
**粗さ（テッセレーション）も指定できる**。⚠️ 粗さは荒めから試すこと。

⚠️ ①②はどちらも**自分の PC の中だけ**で終わります。**ファイルは外に出ません。**

**② CAD Assistant（Open CASCADE 製・無償・Windows）**
STEP を読んで glTF / GLB に書き出せます。
★このビューアの `occt-import-js` と**同じ OCCT カーネル**ですが、
こちらは**ネイティブ 64bit** なので **WASM の 4GB 制限が無い**。
⚠️ 2.29GB だと数十GB のメモリを食い、数十分〜数時間かかることがあります。

**③ 組立を割って持ってくる（★確実。①②が通らなければこれ）**
サブ組立ごとに書き出す。**2.29GB を1枚で見る必要が本当にあるのかを先に問う**
——普通は「いま見たい範囲」だけで足ります。E-BOM 突き合わせも部分でできます。

### 書き出した GLB が大きすぎるとき（★ここが実は本番）

STEP が 2.29GB なら、素の GLB でも数百MB・三角形は億の桁になり得ます。
**GLB になっても、そのままではブラウザで開きません。** 落とします：

```bash
npx @gltf-transform/cli dedup   in.glb  a.glb
npx @gltf-transform/cli instance a.glb  b.glb
npx @gltf-transform/cli simplify b.glb  c.glb --ratio 0.25 --error 0.002
npx @gltf-transform/cli draco    c.glb  out.glb
```

- `dedup` / `instance` — **同じボルトが1000本**あるような組立に一番効きます
  （形を1つにして置き場所だけ持つ）。⚠️ ここで一番減ります
- `simplify` — 三角形を減らす。⚠️ **形が変わります。** `--error` は元の
  外形に対する比なので、**寸法を測る用途では上げないこと**
- `draco` — 圧縮。ビューアは `DRACOLoader` を入れてあるので**そのまま読めます**

⚠️ **測るなら `simplify` を通さないこと。** このビューアの計測はもともと
   「三角形に割った形の上」の近似（だから `~` を付けている）で、
   `simplify` を通すと**その近似がさらに粗くなります**。

## 🔴 ローカルでの動作確認の口（`window.__viewer`）

**このページは STEP を用意しないと何も確かめられなかった。**
カメラの向き・断面の切り方・蓋の描画・階層の読み方は STEP と無関係なので、
**`localhost` のときだけ** `window.__viewer` を開けるようにした。

```js
// 箱と円筒でカメラと断面を測る

g.add(new T.Mesh(new T.BoxGeometry(100,60,40),

V.viewTo('iso');
V.setSec(true, 'x', 560, false);
console.log(V.sec.capColors, document.getElementById('secval').textContent);

// occt と同じ形の入れ物を渡して階層の読み方を測る
V.setModel(V.nodeToGroup(root, { meshes }, { tri:0, vtx:0 }));
```

## 踏んだこと

### 🔴 GIS の読み込みを「待つ」（1回目は開けて2回目でエラーになった）

`#id=` で開いたとき、**GIS（`accounts.google.com/gsi/client`）の読み込みを待たずに
在るかどうかを1回見て諦めていた**。あれは `async defer` なので module の実行より
後に来ることがある。

- **1回目**：three.js を jsDelivr から落とす時間で GIS が間に合う → 開ける
- **2回目**：キャッシュで全部速いので **module が GIS を追い越す** → 「Google の
  ログインを読み込めていません」

⚠️ **スマホ固有ではない。** キャッシュの有無で決まる競合。
→ `gisWait()` で**在るまで待つ**（15秒で諦める）。0.4秒を超えたら
「読み込んでいます…」と出す（黙って待たない）。

### 🔴 リロードで毎回ログインを求められるのは意図どおり（ポップアップの確認は違う）

実機で「Safari でリロードすると毎回ログインを求められる」と指摘された。
**2つの別の話が同時に見えている。**

| 見えるもの | なぜ | どうしたか |
|---|---|---|
| **リロードでログインを求められる** | トークンを**変数にしか持っていない**（保存しない）| ★**意図どおり。変えない**（下記）|
| **「このサイトではポップアップウインドウが開きます」** | `#id=` で開いた直後に**自動で**トークンを要求していて、**タップと紐づいていない**。Safari はそれを止めて聞く | ✅ **直した**（下記）|
| **毎回アカウント選択・同意が出る** | `prompt` を指定していなかった | ✅ `prompt: ''` を付けた |

**① トークンは保存しない。**`sessionStorage` に置けばリロードをまたげるが、
**アクセストークンを web storage に置く**ことになる。これは図面が読める鍵なので置かない。
⚠️ 有効期限は約1時間で、切れたときの再取得も同じ経路を通る。

**② `prompt: ''`（出す必要が無ければ画面を出さない）。**
一度許可した人には**アカウント選択も同意も出ない**。これが無いと**リロードのたびに
選択画面**が出る。

**③ 🔴 読み込みは「タップから」始める。自動で読み込まない。**

`requestAccessToken()` は **必ずポップアップを開く**。`prompt: ''` はポップアップ
**の中**の同意画面を省くだけで、**窓そのものは開く**。
★つまり **「黙って試す」経路は存在しない。**

Safari は**ユーザー操作と紐づかない**ポップアップを止めて聞くので、
`#id=` で開いた直後（＝タップが無い）に自動で要求すると、**毎回あの確認が出る**。

⇒ `#id=` のときは `tapToLoad()` で**タップを待つ**。押した先は、既に許可済みなら
画面が出ずに読み込みが始まる。

⚠️ **自動要求に戻さないこと。** 一見親切だが、確認が毎回出る方が煩わしい。
⚠️ 「押してください」だけ書かない。**押すと何が起きるか**を書く。

## 🔴 ページごと飛んで戻る（ポップアップを使わない。これが本線）

`#id=` で開いたときは **Google へページごと飛んで戻る**。ポップアップもタップも要らない。

| 経路 | 何が起きるか |
|---|---|
| 許可済み・ログイン中 | **画面が出ずに戻ってくる**（`prompt=none`）→ そのまま読み込み |
| 未許可・未ログイン | 「Google の画面へ進む」を出す → 押すと**ページごと**飛ぶ（1回だけ）|
| トークン切れ（約1時間）| **黙って取り直す**（`prompt=none` でもう一度飛ぶ。1回だけ）|
| `REDIRECT_URI` が空 | ポップアップ方式（1回タップ）に落ちる |

### 設定（★これをやらないと Google のエラー画面が出る）

`config.js` の `REDIRECT_URI` と**同じ文字列**を Google Cloud に登録する。

| 欄 | 入れるもの |
|---|---|
| 承認済みの **JavaScript 生成元** | `https://shuichihiratsuka-hash.github.io`（★ドメインだけ）|
| 承認済みの **リダイレクト URI** | `https://shuichihiratsuka-hash.github.io/plm-viewer/`（★末尾の `/` まで）|

⚠️ **別の欄。両方要る。** ⚠️ 1文字でも違うと `redirect_uri_mismatch` になり、
**Google のエラー画面**が出る（こちらには戻ってこないので画面で説明できない）。

### 実装の決めごと

- ⚠️ **`state` に id と hint を入れて持ち回る。** 飛んでいる間 `#id=` は消える。
  ★`state` は**エラーのときも返ってくる**ので、「もう試した」の印（`r`）も入れて
  **無限に飛ばない**ようにしている
- ⚠️ **戻ってきたらトークンを URL から消す**（`history.replaceState`）。履歴・共有に残さない。
  `#id=` は残す（そのままリロードできる）
- ⚠️ **`prompt=none` が通らないのは失敗ではない。** 同意かログインが要るだけなので、
  「進む道」を出す。**一度許可すれば以後は画面が出ない**と書く

### 🔴 枠の中のボタンが押せなかった（`pointer-events`）

`#ph`（真ん中の枠）は `position:absolute; inset:0` でキャンバスに重なるので、
**モデルを回すドラッグを吸わないよう `pointer-events:none`** を付けている。

⚠️ **これは中のボタンにも効く。** 戻していなかったので、
**「Drive から読み込む」「もう一度」「Drive で開く」の3つが全部押せなかった**
（押すと素通りして裏のキャンバスに行く／2026-08-23 に実機で踏んだ）。

```css
#ph{ … pointer-events:none }
#ph button,#ph a{ pointer-events:auto }   /* ★これを忘れない */
```

★**見えていて押せないものは「壊れている」と読まれる。**
枠の中に操作を置くときは必ず `auto` を戻す。

### 🔴 `<input type="file">` に `accept` を付けない

`accept=".stp,.step,…"` を付けていたら、iPhone の**ファイル選択で全部グレーアウトして
選べなかった**（2026-08-23 に実機で発生。OneDrive に落とした `.stp` が選べない）。

iOS は `accept` を **UTI（ファイル種別の識別子）の一覧に翻訳**するが、
`.stp` / `.step` には登録された UTI が無く、`application/step` も認識されない。
結果として**許可リストが空同然になる**。

→ **`accept` を付けず、種別の判定は JS（`kindOf`）でやる。**
⚠️ 読めない拡張子を渡されたら**そう言う**（変換に投げて意味不明な失敗にしない）。
